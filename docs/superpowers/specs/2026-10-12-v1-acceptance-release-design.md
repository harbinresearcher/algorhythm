# 首版设计基线：验收、发布与后续工作

日期：2026-10-12。状态：验收要求已确认；本文件中的 AC 项不是已通过结果。实际检查记录只写入 [STATUS](../../STATUS.md)。统一入口见 [CONTINUITY](../../CONTINUITY.md)。

## R-01：交付与证据

首版是可以连续使用和恢复的受控内测版。小范围代表内容贯通完整过程，再扩大内容与支持范围。覆盖少不等于可以忽略保存、隐私和错误处理。

每次交付说明对应条款、改动文件、提交版本、运行环境、测试输入、实际结果和未验证边界。工程测试、浏览器模拟、真实平台接入、真实模型评估和学习效果分别报告。

规格是行为依据，schema 是接口唯一来源，STATUS 是当前工作记录。总架构负责跨模块边界和集成审查，编码与前端会话按短交接任务工作。数据库、共享类型先统一，再并行接入；不因文档已合意自动授权修改其他会话工作区或合并 PR。

## R-02：验收目录

- AC-01 追溯：题目版本、尝试、会话、动作和来源可查；无关联时明确缺失，非尝试型记录不强迫伪造尝试。
- AC-02 契约：网页、侧栏、核心共享 schema；非法字段、版本、权限、状态和重复 ID 冲突被拒绝；错误不破坏事实。
- AC-03 并发恢复：刷新、暂停、结束、切题、多标签、新尝试与迟到响应，均不污染当前状态；恢复不自动调用模型。
- AC-04 教练故障：401、429、500、超时、断网、非法 JSON、越权提议与恶意题干均有固定用例；已有尝试保留，费用与请求结果未知时不作承诺。
- AC-05 排期：固定输入、时钟、规则版本与受控随机条件下可重放安排；推荐展示到期、帮助证据与预算依据；用户评分才更新 FSRS。
- AC-06 力扣：DOM 与提交 fixture 测试加支持环境的真实验证；题目、提交代码、结果一致；结构变化进入可恢复错误态。错配阻止发布。
- AC-07 数据：成功提交的记录可重开数据库恢复；故障注入覆盖事务失败、配额不足、迁移失败；支持版本备份 round-trip、冲突与旧版迁移有测试。
- AC-08 隐私：Key 不出现在学习包与诊断包；权限、XSS、数据发送授权、删除与外部备份边界均有检查。故障与恶意输入不能提升程序权限。
- AC-09 教学：固定场景经过人工 rubric；检查事实、帮助权限、可继续的一步与误判修正。模型自评不是唯一评判。
- AC-10 内容：默认路线中内容来源及使用许可可核实；变式有正确性与教学适配审核记录；Python 完整验收，其他语言明示边界。
- AC-11 诊断：用动作链定位模拟的丢失、错配与恢复失败；诊断包脱敏；存储失败时仍能向用户说明未保存及可恢复内容。
- AC-12 发布：支持矩阵中的环境通过完整流程、键盘操作、屏幕阅读器语义及非颜色唯一提示检查；记录性能、依赖与恢复路径。

## R-03：教学评估口径

固定六类场景：完全没思路、缺少前置知识、有思路写不出代码、教练误判、主动要求讲解、疲劳暂停。每类使用可重复的输入与行为预期，保留不同正确回答示例；不采用逐字匹配答案。

人工 rubric 至少检查：知识正确、没有越过用户选择的帮助范围、任务适合当前线索、用户有下一步可做、误判能否修正、是否过度提问。知识错误、越权完整泄题和伪造判题结果为严重缺陷；严重缺陷修复后重测，不能靠总分平均掩盖。

试用指标必须保留分母与观察条件：

- 独立完成：在已知帮助范围内完成题目；无帮助记录但外部帮助未知的样本单独报告，不归为已证实独立。
- 提示后继续尝试：实际收到帮助后出现有内容的后续尝试；不是点击继续按钮。
- 延后保持与相关新题迁移：说明间隔、难度、是否曾见过和帮助使用；缺失后续样本不能记为失败或成功。
- 放弃：区分用户明确放弃、疲劳暂停、换题与失访；不从关闭页面推断。
- 反指标：帮助依赖、过度提示、知识错误、认知负荷与挫败感；主观体验来自用户反馈，不由模型代填。
- 效率：选题、找资料、整理记录所花时间与后续表现一起观察，不只比较总学习时长。

先建立基线，再设改进目标。少量连续试用用于发现问题，不宣称普遍或因果性的学习提升。满意度、题量与聊天次数只能辅助解释。

## R-04：发布与性能约束

首轮只承诺一个已测浏览器版本范围和一个站点；日期内部保存明确时间点，展示遵循时区与格式设置。模型、提示、内容、schema、调度规则和实际 FSRS 配置都要能追溯。

性能验收先固定设备、浏览器、数据规模、动作与测量方法，再给延迟和资源阈值。不能用“不卡”“不崩”替代指标，也不能把没有测量的数字说成已达标。

有版本记录、依赖及许可清单、最小功能停用机制、数据库升级保护和兼容性检查。远程灰度平台、完整云同步与自建签名系统不进入首版。按实际分发渠道落实构建来源、签名或商店要求、SBOM 与安全披露方式。

结构错误、数据错配、密钥泄露、破坏性迁移、严重教学缺陷阻止相关能力发布。停用能力后仍应能读取、导出已有数据。涉及不可逆迁移时先验证备份恢复，旧代码不兼容新数据则拒绝假回滚。

## R-05：用户提供的 12 类评审材料归属

1. 领域模型与状态机 → D-01 至 D-03，AC-01 至 AC-03。采用多个关联状态机，所有类型同源。
2. 教练编排 → C-03、C-04、D-04，AC-03、AC-04。首版单次模型调用；判断存依据，置信度不冒充概率。
3. FSRS 与知识映射 → C-05，AC-05。表现证据、复习排期和计划分离，不生成伪掌握分数。
4. 力扣接入 → S-01 至 S-03、S-07，AC-06、AC-10。站点采集和许可分别验证。
5. 本地完整性 → D-04、S-04，AC-07。不可覆写历史不妨碍用户删除，云同步机制后置。
6. 安全隐私 → S-05、S-06，AC-08。加密必须说明威胁模型；不能保证任意脚本攻击下安全。
7. 可观测性 → S-06，AC-11。脱敏诊断与授权评估样本分开，故障时日志可能无法落库。
8. 测试发布回滚 → R-01、R-02、R-04，AC-12。门禁先做，复杂灰度后置。
9. 教学评估 → R-03，AC-09。独立应用不要求首次通过，也不默认限时。
10. 内容许可审核 → C-06、S-07，AC-10。Python 是首版完整支持语言。
11. 决策协作 → R-01、R-06。跨模块 RFC 与有后果的架构决定留依据，不给每个小改动增加审批。
12. 非功能需求 → S-04 至 S-06、R-04，AC-12。支持矩阵内验证，扩大站点和浏览器另行评估。

## R-06：验证入口与待决项

跨端通信与数据归属已形成 [扩展工作台场景](2026-10-12-extension-workspace-design.md)：同一扩展内主页面与侧栏，后台统一写入，包含消息语义和 SC-01 至 SC-11。下一步用合成数据做最小浏览器验证，不以真实用户内容做无授权实验。

随后分阶段推进：

1. 接入验证：核查站点与内容使用边界，在允许的真实环境验证一次题目、代码、判题正确关联。未成功前保留人工输入路径，但不宣称自动接入验收完成。
2. 教练验证：准备固定六类场景和人工 rubric；明确调用预算及可用服务后开展真实模型评估。不会因为本轮保存文档而自动使用付费 API。
3. 契约与存储：根据验证结果统一消息、schema、状态和备份 RFC。用户已要求旧 demo 退役，新实现按新规格开发；是否提供旧备份导入需明确支持范围，不自动接管旧浏览器数据。
4. 第一条完整流程：从今日任务到力扣练习、求助、保存和后续安排，交付可验证切片后再铺开内容与视觉细节。
5. 连续试用：审核首批内容，记录基线和用户反馈，修复阻断项后扩大内测范围。

已选定扩展来源部署和后台主写入，验证切片给出草稿保存默认值。仍需总架构处理正式支持版本、字段级 schema、调度与日志保留数值、模型预算、Key 保存策略、备份兼容矩阵、性能阈值和内容审核责任；相应模块实施或发布前不得留给实现者猜测。

对用户的沟通只需说明使用体验、费用与数据方面的影响。已批准的产品方向不重复逐条确认；新收费承诺、公开发布、外部数据操作等仍遵守实际授权。
