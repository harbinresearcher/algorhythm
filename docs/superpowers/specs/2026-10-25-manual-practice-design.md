# RFC-03：任务 04 手动建题与练习记录

日期：2026-10-25。总架构定义，未实现。依照已冻结的“选择自己的题、保留来源、用户专注练习”方向；不改变真实采集 unresolved 的结论。

## M-01：用户能做什么

工作台新增“记录自己的题目”：填写自定标题，可选粘贴力扣中国站题目链接。成功保存后进入既有编辑器，记录自己的思路或 Python 代码；工作台和侧栏均可继续、暂停、记录尝试。题目区显示自定标题、原题链接和“用户手动记录，未读取原题”。不提供题干全文导入，不自动分类或填标题。

标题必填，去除首尾空白后 1–200 UTF-16 单位。链接可空；非空仅允许 `https://leetcode.cn/problems/{slug}/` 及其 description、submissions、solutions 子页面路径，slug 为 1–200 个小写字母、数字或连字符。禁止用户名密码、非默认端口、编码后的路径片段和其他主机。去除 query/hash，统一存为题目根链接。不访问 URL；界面标注“仅保存链接，不自动解析”。链接用新标签打开，noopener/noreferrer。

侧栏不增加建题表单，提供工作台入口，继续使用原会话列表和编辑器。首次建题只要求标题；没有链接的本地原创练习同样可记录。取消不写库。相同链接再次开始可建立不同练习会话，不合并历史。

本轮不记录结构化 AC/WA、自评或帮助等级，不运行代码，不调用模型或 FSRS，不接入任务 03 的合成关联函数。手动笔记即使写了“通过”，也不能变成平台事实或掌握结论。

## M-02：数据契约和持久化

复用 problems、sessions、events、actions 与现有事务；不建第二套笔记表。运行时 schema 继续同源，类型推导。既有两道合成题和历史内容不改写。

- problemKey 扩展为 unique、pair、manual；manual 只是记录种类，不是新增算法模式。
- Problem 使用来源区分的 strict union：原 synthetic-v1 形状原样保留；新 manual-user-v1 为 `{id, key:'manual', title, statement:'', source:'manual-user-v1', url:string|null}`。manual 不接受非空 statement，url 必须已规范化。
- Session 形状保持，仅允许 problemKey=manual；仍为 active/paused。本任务不新增结束、删除、改名或元数据编辑操作，建题时快照固定。
- LearningEvent 原有 source=synthetic-workspace 保留；manual 会话事件使用 manual-workspace。事件/会话/快照必须一致，不可借 source 混入另一类记录。
- 新写命令 `startManual`：既有信封 + sessionId、problemSnapshotId、title、url；不接受调用者提供 source、statement、revision 或 createdAt。服务器验证 title/url 已规范化，拒绝静默改写命令指纹。
- 开始时同一事务写快照、revision=0 的空草稿 active 会话、started 事件与动作回执；时间取后台时钟。同动作同内容幂等，同动作不同标题/URL 为 ACTION_COLLISION。
- 其余 saveDraft、recordAttempt、pause、resume 沿用既有状态规则；创建或切换前先 flush 当前草稿，失败保留输入、不创建新会话。

数据库布局仍为 v2，六张表及索引不变，没有数据重写迁移。这只表示布局兼容，不表示旧程序能读 manual 内容。正式回退必须使用理解新来源和新备份的修复版本；不得回退旧包后清库。

## M-03：版本与旧记录

在线学习及备份消息统一升级 protocolVersion=2。页面 v1 → 后台 v2、页面 v2 → 后台 v1 均应拒绝并提示重新打开；不能把协议不匹配当空库。只读原始快照时允许旧 synthetic 来源与新 manual 来源共存。

历史 action fingerprint 中的 v1 命令保留原文；新增写入使用 v2。旧 committed 回执没有协议字段，内容原样保留。为备份回放保留明确的 legacy v1 命令 schema，不能让 legacy 解析器接受 startManual；在线 handler 只接受 v2。旧动作查询仍可返回原结果，不把旧 fingerprint 改成 v2。

v2 的 `start` 只允许两道既有合成题；manual 只能由 startManual 创建。startManual 的内容须同时匹配 Problem 快照；其他动作从会话对应的快照推导事件来源。客户端不把 problemKey 直接索引 SYNTHETIC_PROBLEMS 作为标题或题干来源，统一从实际快照读取；缺快照显示数据错误，不猜合成题。

## M-04：完整备份

默认导出 `format='algorhythm-backup', formatVersion=2, scope='practice-records-v2'`。仍只包含四张学习表及既有 envelope 字段，不导出 diagnostics、backupImports。四表上限、10 MiB、摘要规范化和非覆盖导入保持任务 02 规则。

v2 支持混合 synthetic/manual 快照、会话、事件和 v1/v2 历史动作。新增来源/URL 必须进入显式导出白名单和严格校验。不得通过删掉 manual 记录继续导出 v1，也不得用可选任意字段放宽所有旧数据。

导入分派按 formatVersion + scope 精确区分：

- v1 + prototype-storage-v1：保留原验证规则、原摘要；仅合成来源、legacy v1 命令。完整接受既有合法 v1 文件。
- v2 + practice-records-v2：严格验证混合四表，legacy 指纹只能描述合法合成动作，新指纹允许新行为。回放每个会话时首事件决定来源及快照约束，后续动作不能更换来源；每个回执快照仍与回放结果完全一致。
- 其他版本或交叉组合拒绝，不猜格式、不静默降级。

原文件规范化摘要在转换前计算。跨扩展只按各协议解析器规范化 extensionId，不修改版本、来源、标题、URL、时间或事实。现有 backupImports 回执结构和条数保持；重导旧 backupId/digest 返回原回执，续练内容不回退。不同版本文件复用 backupId 但摘要变化仍为碰撞。

五表导入事务、跨文件关系冲突、未知结果先查回执、UI 预览取消不落库全部继承。新记录在两端编辑之前，必须先完成 v2 备份恢复测试，不把可靠备份留到以后。

## M-05：展示与错误恢复

保存成功后关闭表单、选中新会话，用既有紧凑状态区域提示成功。无效输入在字段旁说明，保存失败保留表单。结果未知保留同一已确认命令，先查询回执再由用户手动重试；不能换 actionId 重建。

建题按钮、确认按钮和切题共用原互斥与草稿确认机制。保存期间不能重复建题；编辑期间无强制动画或弹窗。标题、链接、笔记只作为文本，不插入 HTML；不把链接或内容写日志。

合成练习仍可见，标为演示；manual 显示“手动记录”。统一原型说明改为“练习记录原型 · 未接入自动采集、AI 或判题”。不更改整体视觉规范、不引入新组件库。沿用简洁深色风格，键盘可完成表单操作，360px 侧栏无横向溢出。

## M-06：验收

- MP-01：有/无链接均可建题；标题为空、超长、恶意 URL、未知字段拒绝；规范化可复现且不访问网站。
- MP-02：建题四表及回执原子提交；写最后回执失败时全部回滚；相同动作不重复建题、不同内容碰撞拒绝。
- MP-03：工作台创建、侧栏续写，关闭工作台仍能保存；刷新、后台重启、浏览器重启后恢复。
- MP-04：新题前 flush 失败不建题，切题保持隔离；未知建题回执按原命令恢复，快速双击不重复。
- MP-05：同链接两次不同会话互不覆盖；标题含 HTML 样式字符串只作文本；URL 无额外权限和网络请求。
- MP-06：旧 synthetic 库读取/续练，历史 v1 指纹与回执不被重写；v1/v2 页面消息不匹配拒绝。
- MP-07：合法历史 v1 文件导入新版本，原回执查询仍成立；混合记录导出 v2 → 独立空配置恢复 → 继续练习 → 再导入不回退。
- MP-08：v2 来源/快照/事件/动作矛盾、无主引用、跨文件归属冲突整份拒绝且五表不变；未来版本与 scope 错配拒绝。
- MP-09：跨扩展 ID 恢复同时覆盖 legacy v1 和 v2 指纹；备份无 Key、日志、个人配置；取消/超限/未知结果沿用原防护。
- MP-10：真实 Chrome 稳定版独立配置验证手动闭环和实际下载/恢复；Chromium 补迟到、冲突及布局边界。明确模拟故障和实际浏览器区别。

原 272 项行为保证继续保留；消息版本更新时可调整在线 fixture 版本，必须另外保留冻结的 legacy v1 文件和回放反例，不能把所有 1 批量替换成 2。任务 03 合成关联模块不得接入实际记录。

本任务证明用户可保存自己的练习，不证明教学有效或真实平台关联。SC-04/08/09 尚未验证边界继续保留。
