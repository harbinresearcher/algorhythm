# ADR-0001：原型备份采用可移植快照与非覆盖导入

日期：2026-10-14。状态：总架构依据既有工程授权确定；尚未实现。适用提交基线 `f2f3e3f`。

## 决定

为现有合成存储原型增加 JSON 快照备份，覆盖题目快照、会话、事件和学习动作回执。导入允许补入缺失记录；同 ID 同内容跳过，同 ID 不同内容整份拒绝。没有强制覆盖、删除或自动合并分支历史。

数据库由 Dexie 版本 1 升到 2，仅增加导入回执表 `backupImports`。原有四张学习表和 diagnostics 的字段、索引、业务语义不变。备份文件版本独立编号，首个文件版本为 1；不是数据库版本 2 的序列化镜像。

导入回执与学习数据在同一事务提交。后台重启或丢响应后，按 backupId 和内容摘要查询已提交结果。回执不能只放 service worker 内存。

## 取舍

1. 只允许空库恢复：更简单，但不能向已有库补入独立会话。本次选择非覆盖导入，仍不解决同一会话不同版本的合并。
2. 整库替换：容易说明，但会删除目标数据，并需要处理旧页面、待确认动作和数据代次。首个备份切片不采用。
3. 自动择新/冲突合并：需判断事实分叉和删除语义，不能只比较时间戳；留给独立规格。

导入回执不是学习事实，不进入导出。学习动作回执进入导出，保证恢复后原动作查询与去重仍成立。跨扩展 ID 导入只转换历史命令中的本地 extensionId，并重建幂等指纹；题目、会话、事件、动作 ID 和学习内容保持原值。

## 升级与回退

升级仅加表，不改写旧记录。必须用实际版本 1 数据库验证升级和保留结果。升级后禁止用旧代码强行打开或清空高版本库；回退应用代码不等于回退数据。

程序员须在独立测试配置先验证从版本 1 导出白名单数据、升级到 2、再导出/恢复的链路。测试前的版本 1 导出使用测试工具读取同一事务的合成数据，不宣称旧应用已有导出按钮。没有旧版个人数据迁移授权；本轮不触碰个人配置。

完整消息、文件、校验及验收约束以 [RFC-01](../superpowers/specs/2026-10-14-prototype-backup-restore-design.md)为准。新增领域表、裁剪历史、删除学习记录或修改现有动作语义时，必须修订备份版本和兼容矩阵，不能仍宣称当前文件覆盖全部数据。
