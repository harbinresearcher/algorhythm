# 首版设计基线：存储与力扣接入

日期：2026-10-12，2026-10-13 对齐 demo 退役。状态：可靠性边界已确认；扩展内后台主写入已选定，仍需原型验证；真实采集、权限许可和备份格式未验收。统一入口见 [CONTINUITY](../../CONTINUITY.md)。

## S-01：数据归属与跨端通信

保留本地优先和前端技术路线；旧 demo 按用户要求退役。本轮不新增后端、账号、云同步或代码执行器。

首版选同一扩展内工作台和侧栏，后台通过统一核心写入扩展 IndexedDB。两种界面发送带版本和动作 ID 的命令，收到持久化确认后才显示已保存。断开时展示真实状态，本地保存补传去重，模型请求不自动重发。

选择依据、消息协议和关闭/恢复验证见 [扩展工作台场景](2026-10-12-extension-workspace-design.md)。扩展页面共用来源存储，力扣内容脚本不直接写该数据库。旧网页数据库不会自动迁入扩展。

多标签写入使用预期版本与事务内核对。过期写入返回冲突，保留用户编辑并重新读取，不静默覆盖。

## S-02：采集边界

先验证一个明确的浏览器版本范围和一个力扣站点；默认由用户触发采集当前题目、当前代码和本次提交结果。完整历史、多站点和后台广泛采集不进入首版承诺。

不读取或导出登录凭据，不绕过验证码或访问限制。登录失效、限流、验证码、页面结构变化和接口失败返回分类错误；保留已有记录并允许恢复。用户手动提供的材料与平台取得的材料保留不同来源标记。

采集仅覆盖用户授权的相关页面和内容。站点支持、扩展 host 权限、消息来源与有效 payload 限制须在接入规格中列清。

## S-03：提交归属

关联证据包含站点、必要的本地账户隔离标识、平台 submission id、题目 slug、语言、提交时间与提交代码哈希。账号隔离只需最小标识，不需要密码或 Cookie。

- 平台提交身份与题目身份优先；时间、代码哈希只辅助确认，不能单凭时间相近关联。
- 保存提交时的代码快照，不能用结果返回时编辑器里已经修改的代码代替。
- 异步判题持续归属于原提交；切题、多标签和会话暂停不改变其身份。
- 同一提交重复采集幂等；来源矛盾时标记待核对，不覆盖已知事实。
- 缺少可靠字段时保留“待关联/结果不可用”，不伪造正确匹配，也不把网络错误记为代码错误。
- 不自动向力扣提交代码。正式提交仍由用户在原平台发起。

题目、提交代码和判题错配是发布阻断项。Fixture 证明解析规则，真实授权环境验证证明对应环境能接入，两者不能互相替代。

## S-04：保存、恢复与备份

- 尝试与请求资格在同一事务预留；模型调用在事务外；结果写入另开事务重新核对资格。
- 草稿说明最近一次成功保存位置；失败不显示已保存。具体保存频率与最大可接受未保存窗口须在实现规格中定义并测试。
- 重启恢复只使用已保存事实，不能因请求失去页面连接就断定服务端失败或未计费。
- 配额不足、浏览器清理、隐私模式和用户删除站点数据有明确提示及边界；不承诺所有条件下永不丢失。
- 备份覆盖题库、会话、尝试、提交、帮助、复习项、计划与模型判断，使用显式白名单；不含 Key、认证头和普通诊断日志。
- 备份快照需一致；导入先检查版本、大小、字段、引用关系与冲突，确认后原子写入或完整失败，不能半份恢复。
- 同 ID 相同内容去重；同 ID 不同事实拒绝静默覆盖。具体导入策略与预览确认写入 RFC。
- 迁移矩阵列出实际支持的历史版本；未知未来版本拒绝导入。旧题库备份可缺练习表，但必须说明缺失，不能补造记录。
- 数据库升级前准备恢复路径。应用回退必须检查数据库版本，不能只回退 JavaScript 就宣称数据可用。

稳定 ID、schema 版本和删除语义现在定义。完整云同步、CRDT、远程冲突解决与 tombstone 生命周期后置；备份恢复是否会复活已删除记录必须让用户知情并可控。

## S-05：秘密与用户数据

Key 不进入模型上下文、学习记录、备份、导出或日志。首版实现规格必须说明保存位置、默认会话保存或持久保存的选择、解锁方式，以及网页、扩展页面和内容脚本的访问边界。当前原型 localStorage 明文存储不能被新设计文档描述成已经加固。

浏览器端加密需要说明威胁模型和密钥来源，不能把“应用自动解密”当成可防所有恶意脚本的保证。XSS 防护、最小权限与秘密隔离独立验收。

首次连接模型服务时说明发送字段和接收方，允许查看实际发送内容、删去不需要的部分并同意；同一授权范围内无需每次弹窗打断。服务、发送范围变化时重新确认。只发送当前任务所需内容，保留删减后的来源边界。

题目文本、模型 Markdown 和外部链接都作为不可信输入处理；禁止借题目内容提升工具权限。具体渲染清洗、链接规则和消息来源验证写入安全测试。

## S-06：诊断、回放与删除

本地结构化诊断记录动作链、状态转换、工具结果分类、请求耗时与模型版本等元数据，不记录完整题干、代码、模型原文或秘密。敏感报错正文不直接写日志。

普通诊断包采用允许字段清单；完整输入输出只进入另行授权、可删除的评估样本。固定样本驱动程序回放与重新请求线上模型是两种操作，后者不保证同样输出并可能计费。

诊断日志需有容量和保留期限；这些数值在实现规格中固定，不能无限增长。存储失败时允许内存最小错误信息、复制诊断和导出尚未保存内容，避免错误日志反复写入同一个失败存储。

默认不上传错误报告；上传须主动同意。删除策略覆盖学习事实、派生判断、本地诊断与配置，明确哪些可单独保留。程序无法替用户删除已经下载或复制到外部的备份，界面需说明边界。

## S-07：内容使用边界

记录题目、题解、测试用例、代码和资源的来源、归属与使用许可。默认路线只纳入已核实的内容；未获核实前优先保留链接和必要元数据，不默认批量缓存、向模型发送或再分发全文。

“用户能打开页面”不能单独证明产品有权采集、缓存、发送或导出。须分别核查支持站点当前条款和具体内容许可。本轮没有完成法律或条款评审，也不预先给出允许采集的结论。
