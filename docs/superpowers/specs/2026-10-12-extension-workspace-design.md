# 场景设计：关掉主页面，仍能在力扣继续练习

日期：2026-10-12。状态：总架构依据用户授权作出的首版设计选择，尚未实现或完成浏览器验收。对应 S-01、D-02、AC-02、AC-03、AC-07。

## 用户看到什么

1. 点击扩展图标，打开完整学习工作台，查看今日任务。
2. 点击题目，在力扣页面思考和提交；按需打开侧栏求助。
3. 关掉工作台标签页，侧栏继续保存当前练习，不提示“请保持网站打开”。
4. 重新打开工作台，看到已经保存的尝试、帮助记录和当前进度，不手动同步。
5. 浏览器异常退出后，重新打开能取回最近一次确认保存的记录；尚未保存内容和未完成模型请求如实标明。

工作台仍是完整 Web UI，不是狭小弹窗。首版它随扩展安装，在浏览器标签页里打开；不是另一个需要持续在线的网站。

## ADR-001：首版选一个扩展、两个界面、一份数据库

选择：Chrome Manifest V3 扩展内包含完整工作台与 side panel，使用扩展来源下的 IndexedDB。后台 service worker 通过统一核心处理命令和业务写入。UI 只提交命令及读取快照，不自行维护另一份权威记录。

理由：主页面关闭不应成为保存的前提。同一扩展来源避免首版承担网站与扩展的双数据库同步、账号和服务器运维。

未选的方案：

- 独立网站持有主数据库：网页关闭后侧栏必须等待重开或维护第二份待同步数据，不适合这个首版场景。
- 网站与扩展各有权威数据库：增加冲突、身份与删除传播，不增加当前学习价值。
- 后端统一存储：能解决多端问题，但同时引入账户、服务部署和运维，当前没有跨设备要求支持这笔成本。

影响：首版需要安装扩展，只承诺同一浏览器配置中的本地体验；卸载扩展和更换扩展 ID 的数据风险要提示并支持备份。独立网站、移动端和云同步以后通过同一核心与导入导出契约接入，当前不建设。

Chrome 官方文档说明，扩展页面、侧栏和 service worker 共享扩展来源存储；内容脚本直接使用 Web Storage 时访问的则是宿主网站存储。[存储依据](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies)

## ADR-002：后台统一写入，但不依赖后台一直活着

```text
[扩展内工作台] ──┐
                 ├── 命令校验 ─── 核心事务 ─── 扩展 IndexedDB
[扩展内侧栏] ────┘                    │
                                      └── 保存确认与新快照
[力扣采集脚本] ───── 授权观察 ─── 来源及题目核对
```

扩展后台不是常驻服务器，Chrome 可以终止它；内存变量不能承担持久化、互斥或去重的最终依据。后台再次收到命令时从数据库恢复，不要求用户等待原进程回来。[生命周期依据](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)

后台只执行短事务与受控命令；不靠定时空请求、长连接或隐藏页面无限保活。网络调用在事务外，调用中被终止时保留已存尝试；不能承诺模型请求跨浏览器关闭继续运行。

## RFC-001：命令与确认的最小语义

所有正式字段由共享运行时 schema 定义，网页、侧栏、核心不另起字段副本。技术验证至少包含：

- 命令身份：协议版本、actionId、动作类型、适用的 sessionId、题目快照 ID、预期记录 revision 和动作内容。
- 来源：后台从 Chrome 提供的 sender 信息核验来源和标签页，不相信 payload 中自称的角色、tabId 或权限。
- 结果：actionId、成功或错误码、已提交 revision；成功响应只能在事务提交后发送。
- 错误：版本不兼容、无权限、引用不存在、状态不允许、版本冲突、ID 内容冲突、存储失败。连接断开只能表示结果未知，不能直接认定写入失败。
- 相同 actionId、相同内容：返回原已提交结果，不重复写入；相同 actionId、不同内容：拒绝。去重检查先于新写入的预期版本检查。

每个写命令在同一事务中完成资格检查、事实写入、revision 增长和结果登记。消息确认丢失时，前端先查询该 actionId 的处理结果；只有纯本地幂等保存命令可用原 ID 补传。模型请求不自动重发。

重连后读取最新快照；订阅消息只是刷新提示，不能成为唯一状态来源。进程内锁不能替代数据库中的去重与版本校验。

最小验证动作只需开始会话、保存草稿、保存合成观察、读取状态、查询动作结果和暂停/恢复。不在这一切片开放模型调用、真实力扣抓取、自动提交或任意工具执行。

## 草稿与关闭

草稿编辑后显示“正在保存”。每次编辑递增本地编辑代次，发出保存时绑定编辑器实例、编辑代次和内容快照；只有确认对应当前编辑内容时才显示“已保存”。旧快照确认到达时，可以更新已提交版本，但不能把随后输入的新内容标成已保存。

同一编辑器同时只发一个草稿写请求，调用期间继续输入的内容留在待保存缓冲；确认并取得新 revision 后再保存最新内容，结果未知则先查询原 actionId。验证阶段采用 500 毫秒无新输入后触发保存；用户主动暂停或切题时立即请求保存，并等待当前内容确认后完成切换。这个数值是工程默认值，不是教学参数，需通过实际体验检查。

用户强制关闭浏览器可能丢失最后一次确认之后的输入；不能用 beforeunload 异步保存假装保证。只有最近一次已确认保存的 revision 属于恢复承诺。

存储满了或消息断开时，内容继续留在仍打开的编辑界面，明确提示未保存并允许复制或导出。浏览器关闭后无法恢复纯内存内容。

## 多标签与换题

当前浏览器标签页不是题目身份。每条命令显式绑定会话和题目快照；切题后递增视图标识，旧请求结果不渲染到新视图。

两个界面编辑同一草稿时使用 revision 检查：后提交的过期版本被拒绝，保留本地文本供用户选择；不能静默用最后写入覆盖。

同一题不同会话分别保存。迟到的真实判题结果只能归档到已可靠匹配的原提交；旧教练反馈按会话与请求资格拒绝成为新会话结果。切题不把旧数据重新归类。

## 来源与权限

工作台和侧栏是可信扩展页面，但其命令仍需校验。内容脚本仅能提交已授权观察；不能读 Key、读取全部历史、删除数据或触发付费模型调用。禁止接受题干中指示的新工具权限。

首轮消息通信只在扩展内部开放，不配置面向普通网页的 externally_connectable 通道。外部文本一律按数据处理，输出用安全文本或受限渲染。Chrome 建议将内容脚本消息视作可能被攻击者构造的数据。[消息安全依据](https://developer.chrome.com/docs/extensions/develop/concepts/messaging)

侧栏由用户操作打开，完整工作台作为扩展页面标签打开；不把自动弹侧栏作为学习流程前提。[侧栏依据](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)

## 验收场景

以下均是待执行用例，不是已通过结果。第一轮使用合成题目和代码，Chrome 稳定版/Windows 11，记录确切版本与扩展 ID。真实接入候选站点为 leetcode.cn，另行核查许可和采集可行性。

- SC-01：工作台开始会话，关闭工作台，侧栏保存尝试；重开工作台读取相同记录与 revision。
- SC-02：强制停止后台再保存；后台重新唤醒，从数据库取回会话，不产生重复记录。
- SC-03：事务提交后丢弃响应；按 actionId 查到原结果，重复本地命令不新增记录。
- SC-04：事务提交前中断；没有伪成功，恢复后可用同 ID 保存，引用关系完整。
- SC-05：两界面用同 revision 改草稿；只接受一个版本，另一个保留文本并收到冲突。
- SC-06：A 题操作延迟后切换到 B；A 的保存和结果仍归 A，B 的界面不展示 A 反馈。
- SC-07：刷新侧栏及重启浏览器；已确认数据可恢复，未确认部分不伪装已保存；不自动请求模型。
- SC-08：配额、事务或权限失败；显示分类错误，可复制未保存内容，错误日志写失败不造成无限循环。
- SC-09：普通网页或内容脚本伪造高权限命令；来源/动作检查拒绝，不改数据或触发调用。
- SC-10：升级协议或扩展实例 ID 不一致；不把不同数据空间显示成“数据丢失”，说明版本或备份导入要求。
- SC-11：A 草稿保存期间继续输入 B，A 的确认迟到；界面仍显示 B 未保存，待 B 确认后才显示已保存。B 尚未提交时关闭只承诺恢复 A；B 已提交但确认丢失时，按实际持久化结果恢复，不能把恢复 B 判作失败。

## 与原基线的关系

本决定落实 S-01 的主存储选择，替代“独立网页与扩展互相同步”的默认假设；产品服务方向不变。用户已经要求旧 demo 退役，新工程从批准规格开始，历史接口不再约束新实现。

这份文档允许编写上述合成数据验证切片。生产 Key 策略、真实站点适配、模型传输生命周期、备份迁移格式和性能门槛仍按各自规格验证，不由这个场景推导为已完成。
