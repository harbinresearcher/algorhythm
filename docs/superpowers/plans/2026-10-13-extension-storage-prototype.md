# 扩展存储与通信原型实施计划

日期：2026-10-13。依据：已批准的[场景规格](../specs/2026-10-12-extension-workspace-design.md)，SC-01 至 SC-11。本轮开发已获用户授权，不重复确认设计。

## 范围与取舍

- 在现有隔离 worktree 的 `feat/extension-storage-prototype` 分支开发。
- 新工程位于 `apps/extension`；不读取或恢复退役应用。React 18、TypeScript、Vite、Dexie；Zod 定义运行时协议并推导类型。只用本地 CSS，无图片、远端字体或新增组件库。
- 合成题目两道，工作台和侧栏共用 UI 与命令客户端；无模型、真实站点权限、采集、判题和教学效果宣称。
- 所有写入通过后台事务。草稿是可变快照；提交尝试与动作结果是不可覆写事实。操作日志只含动作身份、阶段、错误分类。
- 基础 schema 属于协议 v1 原型，不等于整套产品实体/备份迁移契约已完成。
- 浏览器验证用 Playwright 独立持久化临时配置，记录 Chromium 实际版本。原生侧栏与侧栏页面标签测试分别列出；Chrome 稳定版手工安装另外验收。

## 1. 契约与存储

文件：`src/shared/protocol.ts`、`src/core/store.ts`、`tests/store.test.ts`。

1. 建 npm 包和类型/测试/构建脚本，先写存储回归测试，确认空实现不能满足断言。
2. 实现严格 schema、来源白名单、协议/扩展实例校验；事务内先 actionId 去重，再校验 revision，保存快照、事实与结果。
3. 测试重复动作、碰撞、并发版本、暂停/恢复、跨题、事务回滚、重开数据库、配额与权限分类。非法命令只存脱敏诊断。

验证：`npm test -- tests/store.test.ts`；SC-02..06、08..10 的核心不变量。

## 2. 草稿确认与恢复

文件：`src/client/transport.ts`、`src/client/draft.ts`、`tests/draft.test.ts`。

1. 先写延迟确认、继续输入、消息丢失与失败重试测试。
2. 单编辑器串行保存，500ms debounce；确认绑定输入代次。冲突保留输入，显式读取最新版本。
3. 断开后查原 actionId；未知结果留待用户手动恢复，重发使用原 ID。暂停/切题先 flush 当前输入。

验证：SC-03、05、06、11；失败后不能出现虚假的“已保存”。

## 3. 扩展与 UI

文件：`public/manifest.json`、`src/background.ts`、`workspace.html`、`sidepanel.html`、`src/ui/*`。

1. 后台同步注册消息监听，使用 Chrome sender；只授权两个扩展页面。不声明站点权限或外部消息通道。
2. 两个界面打开同一会话、写草稿、记录尝试、暂停/恢复。空态、忙碌、冲突、失败、手动恢复与复制/导出可用。
3. 深蓝灰底、温和蓝色强调；题干/草稿/事实为主，无假统计。窄侧栏单列，宽工作台题目导航与编辑分区。键盘焦点、文本状态提示、系统中文字体。

验证：类型与生产构建通过；真实浏览器检查桌面、窄屏、键盘与主要操作。按技能检查视觉，产品上下文直接使用已冻结规格，不再做重复访谈。

## 4. 验收、交接与集成

文件：`scripts/browser-check.mjs`、`docs/verification/2026-10-13-extension-prototype.md`、CI、README、STATUS、CONTINUITY。

1. 隔离浏览器加载构建产物，复现关闭工作台、后台停止、重复命令、重启恢复、多窗口冲突。记录截图与 SC 证据。
2. 注入故障只在测试层，通过数据库适配/传输函数，不在发布包留远程测试命令。
3. 恢复 CI 的 install/typecheck/test/build，保留文档与提交范围空白检查。
4. 独立代码审查并修复，实际命令全绿后提交、推送并建 PR；不自动合并其他 PR 或改仓库设置。

不把单元测试当浏览器验收；没有实测的场景明确留空。无需对低影响排版写镜像测试。
